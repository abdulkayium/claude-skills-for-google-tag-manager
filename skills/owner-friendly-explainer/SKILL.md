# Owner-Friendly Explainer

Turns tracking language into business language.

## Use this when
- A client or boss asks "why does this matter?"
- A technical finding needs a plain version.
- A proposal needs a clear "why" section.

## Inputs to ask for
1. The technical issue or topic.
2. The audience and what they care about (sales, cost per lead, trust in reports).
3. Any real numbers that can be used.
4. The length wanted (one line, one paragraph, a short message).

## Workflow
1. Name the problem in one plain sentence.
2. Say what the business sees (for example, "ads show leads, sales team says they are not real").
3. Say what it costs: wasted spend, wrong decisions, slower growth. Use real numbers only if given.
4. Use one simple comparison, like a till that misses some sales.
5. Say how it is fixed in two or three plain steps.
6. Say what is needed from the owner, if anything.
7. Repeat the key point once in the simplest words.

## Output format
- A short version: 2 to 3 sentences.
- A longer version: a short message with the steps above.

## Decision rules
- Short sentences. Common words. One idea per line.
- Replace jargon: "conversion" can be "a sale or a lead", "tag" can be "a small piece of code that counts actions".
- If a technical word must stay, explain it once in brackets.
- If the point is a warning, keep it calm and factual.

## Guardrails
- Writing only. Do not send the message or change any system. Give the text for the user to send.
- Do not exaggerate fear. Do not say "you are losing money" without data.
- Do not promise results.
- Do not talk down to the reader.
